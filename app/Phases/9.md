# App Phase 9 – System Menu & Modals

## Status

Implemented. The Aqua system menu lives in the Menu Bar (`SystemMenu.tsx`, fixed glyph, clock/sleep overlay), shared confirmation/elevation/prompt dialogs are mounted once at the desktop root (`ModalHost`), and Finder retries failed filesystem ops through the elevation flow. Tauri host owns lifecycle commands only: `restart_daemon` (graceful `POST /api/system/shutdown` first), `relaunch_aqua`, `quit_and_stop_daemon`, `get_distro`.

## Design

- Follows `../design/UI-SPEC-08-Modals.md`: centered 380px overlay panels on a 50% `--bg-base` scrim, strictly modal (Esc = cancel, focus trap via `useModalBehavior`, no click-outside dismiss).
- Confirmation buttons: Cancel left/secondary, affirmative right — `--status-danger` fill when destructive, `--accent` otherwise. `Enter` activates the affirmative action only for non-danger confirms.
- Elevation modal names the requesting app and the exact operation, shows a read-only user field, clears the password from React state the moment the request fires (never retained for retries or logs), shakes once on a wrong password, and shows an inline spinner while in flight.
- The Settings… menu item is present but disabled — its slot is reserved for Phase 10.

## Deliverables

- `desktop/SystemMenu.tsx` — About panel (app/daemon version, distro), Force Quit list, Restart Daemon (confirm when connected), Sleep Display, Restart Aqua, Shut Down Aqua
- `system/modalStore.ts` + `ConfirmModal` / `ElevateModal` / `PromptModal` + `ModalHost`
- Finder `needsElevation` → ElevateModal → retry-with-`elevated:true` loop in every CRUD path
- Tauri commands wired to graceful daemon shutdown per contract
