# App Phase 1 - Window Manager Core

## Outcome

A single Aqua Space supports multiple generic app windows with correct open, focus, drag, resize, edge-snap, minimize, restore, and close behavior.

## Prerequisites

- Phase 0 shell and daemon connection state are stable.
- No feature-specific backend endpoint is required.

## Deliverables

- App manifest model containing app ID, name, React Icon component, default/minimum size, Dock behavior, and menu config.
- Zustand window store for window/app identity, position, size, z-order, minimized, focused window, and single initial Space.
- Generic `WindowFrame` per `DESIGN.md` + `app/design/UI-SPEC-01-Chrome.md` §3 (28px title, 12px lights 8px gap 16px inset at 60%→100% + glyphs on hover, focused 100% unfocused 35%, centered em-dash title, 4px invisible handles, 220ms open/close from Dock rect, 320ms minimize-to-Dock). GPU-only `transform`/`opacity` via `framer-motion`.
- Focus/z-order without unbounded z-index growth; transform-based drag/resize with pointer capture and RAF-batching.
- Edge-snap, maximize/restore with bounds preservation, minimize-to-Dock (320ms).

## Not In Scope

- Finder or other feature app internals, multiple Spaces, persistence, final Dock magnification (placeholder panes are allowed).

## Design refs

- `DESIGN.md` (tokens/motion) + `app/design/UI-SPEC-00-INDEX.md` + `UI-SPEC-01-Chrome.md` (Menu Bar / Dock / Window Frame — 4 states, global connection dot, magnify, traffic lights, animations).

## Verification

- Unit-test store transitions; component-test traffic lights and keyboard access; manual pointer-capture checks; reduced-motion audit.
