# Backend Phase 4 – Spotlight backend

## Status

Implemented and verified for the current Linux/WSL backend scope. The daemon provides bounded Tantivy filename/content search, calculator and unit-conversion actions, app metadata, startup indexing, and debounced incremental filesystem updates. The index is intentionally in memory: a daemon restart discards it and performs a fresh bounded index build, which is the documented recovery behavior. Windows-to-WSL reachability remains an external Windows-native verification step.

Provide fast file and content search, app metadata, and deterministic quick actions for Spotlight.

## Depends on

- Phase 1 filesystem path policy and watch infrastructure
- Search shapes in `../../CONTRACT.md`
- Explicit index roots, exclusions, storage location, and size limits

## Deliverables

- A Tantivy index schema and index lifecycle
- Initial indexing at daemon startup
- Recursive walking that respects configured roots and exclusion rules
- Incremental index updates driven by debounced filesystem events
- `GET /api/search?q=` returning files, apps, and actions
- File-name and supported text-content search
- Ranked results with stable score semantics
- Calculator and unit-conversion quick actions where specified
- App-launch metadata understood by the frontend without executing apps in the daemon
- Explicit reindex behavior for corrupted or incompatible indexes

## Correctness and safety

- Never index outside allowed roots.
- Do not follow excluded or escaping symlinks.
- Skip binary, oversized, unreadable, and unsupported files safely.
- Bound query length, result count, indexed content size, and concurrent work.
- Do not trigger a full reindex for routine watch events.
- Avoid logging private indexed content or full queries at sensitive log levels.

## Acceptance criteria

- [x] Startup indexing produces searchable file-name results.
- [x] Supported text files produce content hits and snippets.
- [x] Create, modify, rename, and delete events update the index incrementally.
- [x] Excluded and out-of-root files never appear.
- [x] Binary and oversized files are skipped without failing the indexer.
- [x] Search results match `CONTRACT.md` and are deterministically bounded.
- [x] Quick-action parsing has representative correctness and failure tests.
- [x] Recovery after in-memory index discard is tested; persistent corrupt-index migration is not applicable.
- [x] Formatting, Clippy, and all tests pass.

## Recovery and reindex behavior

The current index uses Tantivy's in-memory index and is never persisted to disk. This avoids search-index filesystem-watch feedback loops and keeps private indexed content out of daemon storage. If the process exits or the in-memory index is discarded, startup creates a new index and rebuilds it from the configured roots; this fresh-reindex path is covered by a unit test. Persistent corrupt-index migration is not applicable until a disk-backed index is deliberately introduced.

## Out of scope

- Spotlight React UI or global hotkey
- Arbitrary command execution from search input
- Windows Start-menu indexing
- Cloud or network search
