# Backend Phase 3 – Activity Monitor backend

## Status

Implemented and verified with contract-focused WebSocket integration tests. The daemon now exposes shared, once-per-second `sysinfo` polling through `WS /ws/sysmon`. CPU values are the normalized system-wide percentage reported by `sysinfo::System::global_cpu_usage()`; memory and disk values are bytes. Windows-to-WSL reachability requires restarting the running daemon with this build.
## Goal

Stream read-only WSL system statistics to Aqua at a stable interval.

## Depends on

- Phase 0 server foundation
- Sysmon shapes in `../../CONTRACT.md`

## Deliverables

- A `sysinfo`-based polling service
- `WS /ws/sysmon`
- Approximately one update per second
- CPU percentage
- Used and total memory in bytes
- Disk usage by mount
- Process PID, name, CPU percentage, and memory bytes
- Shared polling so multiple clients do not each trigger a full independent system refresh
- Poller cleanup when no longer needed or during shutdown

## Behavior

- Emit camelCase `SysmonStats` frames matching `CONTRACT.md`.
- Document whether CPU values are per-core or normalized system percentages.
- Use stable byte units and avoid frontend-specific formatting.
- Handle processes disappearing between collection steps without failing the stream.
- Keep this API read-only; no kill, signal, priority, or renice endpoint belongs in this phase.

## Acceptance criteria

- [x] Every emitted frame matches the documented sysmon shape.
- [x] Numeric fields are finite and use documented units.
- [x] Process churn does not crash or close the stream.
- [x] Multiple clients share bounded backend work.
- [x] Disconnects release subscriptions cleanly.
- [x] The update interval does not create an uncontrolled task backlog.
- [x] No process-control endpoint is exposed.
- [x] Formatting, Clippy, and all tests pass.

## Out of scope

- Activity Monitor UI
- Historical metrics storage
- Process termination or priority changes
- Host Windows metrics outside WSL
