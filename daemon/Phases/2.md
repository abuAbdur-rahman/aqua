# Backend Phase 2 – Terminal backend

## Status

Implemented and verified for the current Linux/WSL backend scope. The daemon provides Origin-gated, single-attachment PTY sessions with binary I/O, resize control, exit notification, heartbeat timeout, unattached-session expiry, and cleanup on disconnect or daemon shutdown. Windows-to-WSL reachability remains an external Windows-native verification step.

## Goal

Provide real bash PTY sessions through a REST spawn endpoint and a bidirectional WebSocket bridge.

## Depends on

- Phase 0 server foundation
- PTY shapes and framing rules in `../../CONTRACT.md`
- The approved localhost trust boundary and exact Aqua WebView Origin allowlist documented in `../../CONTRACT.md`

This phase deliberately preserves the localhost/no-auth architecture. Exact Origin validation is mandatory browser hardening for both PTY endpoints, but is not represented as authentication against native processes running as the same user.

## Deliverables

- A `portable-pty` session manager
- `POST /api/pty/spawn`
- `WS /ws/pty/:sessionId`
- Input forwarding from WebSocket to PTY stdin
- PTY output forwarding to WebSocket clients
- Resize handling for `cols` and `rows`
- Exit notification containing the process exit code
- Session cleanup on disconnect, timeout, daemon shutdown, and failed startup
- Structured logs using session identifiers without logging terminal contents

## Protocol requirements

The framing and lifecycle rules are fixed in `../../CONTRACT.md`:

- PTY input and output use binary frames only;
- text frames are strict JSON resize/exit control messages;
- malformed or unsupported application frames close with policy error `1008` and terminate the session;
- the daemon sends a ping every 15 seconds and terminates sessions that do not pong within 10 seconds;
- sessions have one WebSocket attachment and cannot be reattached;
- unattached sessions expire after 30 seconds;
- spawn and resize dimensions are bounded to `1..=1000`;
- both PTY endpoints require an exact approved Aqua WebView Origin.

Use `sessionId` consistently in route and JSON-facing terminology.

## Acceptance criteria

- [x] A valid spawn request starts a PTY in the requested or default working directory.
- [x] Invalid dimensions and working directories return structured errors.
- [x] Interactive input and output preserve bytes correctly.
- [x] Resize messages change PTY dimensions.
- [x] Process exit produces the documented exit frame.
- [x] WebSocket disconnect and heartbeat timeout do not leave orphaned shells.
- [x] Daemon shutdown cleans up all child processes.
- [x] Concurrent sessions remain isolated.
- [x] Sensitive terminal content is not written to logs.
- [x] Formatting, Clippy, and all tests pass.

## Out of scope

- Terminal React or `xterm.js` UI
- Session persistence across daemon restarts
- Remote shell access
- Command filtering or sandboxing
