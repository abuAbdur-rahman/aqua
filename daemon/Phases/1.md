# Backend Phase 1 – Finder backend

## Status

Implementation complete for the current Linux/WSL backend scope. Filesystem operations use `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS` and descriptor-relative mutation APIs; the race-focused confinement test passes.

## Filesystem policy

- The production allowed root is the daemon user's canonical `$HOME` directory.
- Relative paths resolve beneath that root; absolute paths are accepted only when their canonical target remains beneath it.
- Parent traversal components are rejected.
- Symlink entries are listed as symlinks. Operations that follow a path reject symlink traversal; rename, move, and delete operate on directory entries without following symlink targets.
- Linux/WSL operations use `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS`, plus descriptor-relative `renameat`, `unlinkat`, `mkdirat`, and `fchmod` calls to resist concurrent replacement.
- The allowed root itself cannot be renamed, moved, or deleted.
- File reads return at most 1 MiB. Larger files set `truncated: true`; returned bytes are UTF-8 when valid and base64 otherwise.

## Goal

Implement the filesystem API required by Finder and the editor: safe directory listing and file reading first, then mutations, file writing, and live filesystem events.

## Depends on

- Phase 0 health and server foundation
- The filesystem shapes in `../../CONTRACT.md`
- An explicit decision defining allowed filesystem roots and symlink behavior

Do not begin mutation endpoints until the allowed-root policy is documented and testable.

## Deliverables

### Read operations

- `GET /api/fs/list?path=` returning `FsEntry[]`
- `GET /api/fs/read?path=` returning `FsReadResponse`
- Correct file, directory, and symlink classification
- Byte size, ISO 8601 modification time, and octal permissions
- UTF-8 content when valid; base64 when required by the contract
- A documented truncation limit for large files

### Mutation operations

- `POST /api/fs/op` supporting `createFile`, `createDir`, `rename`, `move`, `delete`, and `chmod`
- `PUT /api/fs/write`
- CamelCase tagged-union decoding matching `CONTRACT.md`
- Structured success and error responses
- Safe behavior for collisions, missing parents, invalid names, and cross-filesystem moves

### Filesystem watching

- `WS /ws/fs-watch`
- Subscribe and unsubscribe messages
- Created, modified, removed, and renamed events
- Per-path event debouncing to prevent `notify` event storms
- Watch cleanup when clients disconnect

## Security and correctness

- Resolve every operation relative to an opened root directory descriptor.
- Reject `..`, absolute paths outside the configured root, and symlink traversal.
- Keep entry mutations descriptor-relative so concurrent path replacement cannot redirect an operation outside the root.
- Prevent deleting or moving an allowed root itself.
- Apply the same policy to list, read, write, chmod, rename, move, delete, and watch operations.
- Do not rely on frontend validation.

## Acceptance criteria

- [x] Read-only list and read endpoints match `CONTRACT.md`.
- [x] Mutations match the `FsOp` tagged union exactly.
- [x] UTF-8, binary, empty, large, and permission-restricted files have tested behavior.
- [x] Traversal and symlink-escape attempts fail safely in tests.
- [x] Rename and move events have deterministic contract behavior.
- [x] Watch bursts are debounced and disconnected watchers are released.
- [x] No endpoint can operate outside configured roots, including under concurrent path replacement.
- [x] Formatting, Clippy, and all current tests pass.
